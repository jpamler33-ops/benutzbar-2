## 2026-11-02: Map tile policy compliance + mobile map visibility (PR #6)
- **Root cause confirmed in code and official OSM policy:** `app.js` set `img.referrerPolicy='no-referrer'` on all OSM XYZ images. OSM's tile server policy requires browser Referer and explicitly forbids suppressing it; blocked map tiles are a possible direct consequence. Official source: https://operations.osmfoundation.org/policies/tiles/
- **Fix:** `strict-origin-when-cross-origin` on tile requests and HTML; map status only shows ready after an image load, errors surface a banner, and failed tiles retry once when the browser reports reconnection. Normalized zoom coordinates. Removed unreadable extreme map tile color filtering; in the mobile layout OSM attribution is moved above the collapsed drawer; removed a 480px minimum-height trap on short phone screens.
- **QA root cause:** public feed contains a legitimate category-vetted Croatian shore-fishing *editorial* item with no proven region or catch. The existing QA gate incorrectly required every item to match the regional forum classifier, turning main CI red. Fix accepts only configured enabled/approved editorial sources with zero relevance and no geo/country labels; rejects off-source article links, invented regional labels, and unknown source IDs.
- **Tests:** New `tests/test_map.js` executes real `app.js` in a minimal networkless DOM mock, checking tile URLs, Referer policy, viewport-limited tile requests, drag, zoom, success/error status, visible attribution CSS and HTML meta. New `tests/test_public_quality.py` covers accepted editorial and rejected fake location cases. PR CI verified green on 2026-11-02, including existing Geo/RSS suites. Browser imagery and iPhone Safari in production have **not** been independently live-verified.
- **Remaining risks:** Actual OSM tile requests may fail for user-specific network reasons, external rate limiting or browser privacy settings; no paid fallback service is enabled. Keep future user reports/screenshots as evidence, and do not bulk-prefetch OSM tiles.

## 2026-11-02: private catch backup restoration hardening (PR #8)
- **ROOT CAUSE:** `free-store.js` validated imported records but reconstructed them without `evidence_status`, `review_note` or `weather_error`. The JSON export included those fields, so export → delete → import could silently discard user-entered manual source reviews and weather-history warnings. The import confirmation also counted duplicate entries as newly imported.
- **PATCH:** `restoreBackupRecord()` revalidates each record and restores only allowlisted, bounded metadata. A `source_reviewed` label survives only with a valid HTTPS source link and 12–300-character review note; model-weather statuses cannot assert available data without weather payload. Timestamps are validated; original UUID, weather data, wind metadata, and notes survive. Malformed imports cannot partially write; duplicates do not overwrite existing private entries, and the UI reports only newly added rows. All data stays in browser localStorage; no changes to real user records or remote storage.
- **TESTS:** `tests/test_private_backup.js` invokes the real browser storage module and `exportData()` Blob, deletes the test records, imports the same JSON and asserts ID/field integrity, reviewed metadata, weather error, duplicate zero-add result and atomic rejection of malicious/oversized JSON. GitHub standard QA green; full 10× QA loop green with `PRIVATE_BACKUP_ROUNDTRIP_OK` in each round, and 10 headless Chrome desktop/mobile rounds green. Code PR checks: 41520073531 (normal) and 41520073081 (10×).
- **REST-RISIKO:** localStorage can still be erased by OS/browser cleanup. Export is manual; no cloud backup. Existing backups exported before this fix remain importable in format version 1; metadata missing in old backups cannot be recreated.
